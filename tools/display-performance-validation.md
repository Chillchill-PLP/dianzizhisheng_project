# 显示与开屏帧率调整

2026-10-20；ESP32-S3 / ESP-IDF 5.5.5 / ST7789 240×240 RGB565。

## 改动

- SPI 从 20 MHz 提高到 40 MHz；整屏像素线缆传输理论耗时从 46.08 ms 缩短到 23.04 ms，尚未计入命令、绘图和调度。
- 两块各 16 行（7680 字节）的内部 DMA 缓冲，总计 15360 字节。发送一块时准备下一块；结果回收前不覆盖缓冲或描述符。分配失败回退单缓冲。
- 相近变化区域在额外 128 像素预算内合并，减少窗口命令；静态画面继续零 SPI 更新。动态 UI 最短间隔 17 ms，约 59 次/秒上限。
- 串口新增 `draw`、`flush`、`regions/update` 统计，用于分辨绘图与差分/传输开销；显示仍使用中断等待，优先级低于音频与语音。
- 使用与原工程 GIF 对应的透明 SVG 矢量动画直接按约 30 fps 重新采样，37 帧变为 107 帧。动态间隔 33/34 ms，开头黑场 300 ms、结尾校徽停留 500 ms、总时间轴 4300 ms。沿用原 32 色表，最终校徽 RGB565 像素完全一致。
- 每帧独立压缩，慢速时仍能直接跳过过期帧；不依赖前帧，不把原有帧简单重复或加速。

## 主机验证

使用实际 C 显示和开屏函数，在 TinyCC 编译的 ST7789/SPI 队列模型中检查：47 个场景通过，另有 500 次随机画面变化逐像素匹配。模拟器延迟读取 DMA 数据，检查未完成缓冲/描述符不被提前改写；覆盖全屏/局部/奇数宽度、颜色字节顺序、无变化、单缓冲和无差分缓存、窗口/排队/结果错误与完整恢复，以及真实四宫格、音乐、16 个琴键、设置选择动画和传输页面。

实际 C 解码器逐帧匹配 107 个 RGB565 预期图；检查任意跳帧独立解码、截断/无效色表拒绝、正常时间轴、慢速跳帧、最终画面和 500 ms 最终停留、SPI 错误退出。素材检查确认新帧并非仅重复旧帧，原色表和最终帧保持一致。

## 实机检查

本次未烧录或实测帧率。上述模拟只验证正确性，不能证明开发板达到 30 fps 或面板扫描频率。重新烧录后比较 `NJUPT splash complete` 的 rendered/skipped/max_frame 与 `TFT refresh` 的 draw/flush；同时检查播放、语音、琴键、Wi-Fi 进出时的显示与音频。
